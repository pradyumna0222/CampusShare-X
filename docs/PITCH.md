# CampusShare X — Pitch and Demo Script

## One-line description

CampusShare X helps institutions safely unlock underused equipment and spaces by connecting project-aware discovery to eligibility controls, fair allocation and a traceable sharing lifecycle.

## 60-second pitch

Universities own valuable equipment and spaces that often remain unused, while students and researchers struggle to access the resources they need for projects. A basic booking calendar cannot fully handle access restrictions, competing requests, handover records and return accountability.

CampusShare X treats each reservation as a controlled resource-sharing transaction. SmartMatch helps users discover equipment by describing their goal. TrustGuard checks verified profiles and mandatory training. FairShare applies transparent usage limits and waitlist rules when demand exceeds availability. The Resource Passport records handover condition, return condition, extension decisions and incidents, while the owner remains in control of approvals and any penalty-related review.

Our aim is to make existing resources easier to share, safer to lend and more useful to the community—without hiding decisions behind an opaque AI model.

## Four- to five-minute live demonstration

1. Sign in as a student and enter: “I need to build an IoT prototype and test a sensor circuit.”
2. Show SmartMatch reasons for the ESP32 starter kit, sensor kit and measurement equipment. Explain that relevance, eligibility and live schedule are separate signals.
3. Open Digital Oscilloscope. Show the `lab-safety` prerequisite and that the student without it cannot submit a request.
4. Request an available ESP32 slot and show it as pending. If possible, submit a competing request with the second student account.
5. Sign in as owner. Approve one request and show the competitor move to the waitlist with a decision reason.
6. Return to the student workspace and perform check-in with an initial condition record.
7. Request a booking extension and show it remains pending; approve it as owner after schedule recheck.
8. Return with a minor condition issue and provide objective notes. Show the resulting incident in the owner's view.
9. Resolve it with a note, then open the audit history and export CSV.
10. Finish by showing the analytics view and state clearly which data are starter records versus measured activity.

## Suggested answer to “What is novel?”

The novelty is not a booking calendar or chatbot alone. CampusShare X combines project-aware resource matching, server-enforced access requirements, transparent scarce-resource handling and a resource-specific condition/audit history in one continuous transaction.

## Claims discipline

Do not claim a percentage increase in utilisation, cost savings, improved fairness or damage reduction without measured evidence. Report the scenarios tested and actual pass/fail results instead.
